# R151 本地两步停止 PPO 冒烟

冻结范围：只检查第二层，不修改第一层、R141 权重和历史结论。CPU 本地运行。

复用 `workflow_core.py` 中的四函数工作量、容量、分组可行性、随机分段泊松到达流、部署成本公式，以及 R121 的单包拆分/完整包迁移动作语义。新实现连续事件执行器，所有请求共享同一条时间线。不是将两个静态窗口评分相加。

三组：单步 PPO；最多两步且允许提前停止 PPO；最多两步并屏蔽提前停止 PPO。最后一步的保持等价于结束，固定两步组在还有合法新动作时必须调整。相同初始化种子、训练状态和训练请求流、相同环境交互步预算上限；完整 rollout 数可以不同，分别报告。

首次决策 t=0，第二次最早 t=15 秒，且前一次部署完成。60 秒到达窗口，运行至所有请求完成。停止表示本轮不再调整。修复时停止接入新请求，已有请求按旧布局排空，部署完成后等待请求进入新布局；不会清空核、链路或请求。旧包回收后部署新包，不声称在线无缝迁移。部署阶段新请求等待计入响应。两次布局的驻留容量各自合法；不建模临时双版本共存。

排除已访问布局，避免立即往返。第二步观察真实已到达请求、待执行 CPU 工作量、未完成请求、剩余内存、已花费部署/排空时间；不读取未来请求或候选仿真收益。

沿用普通候选打分 MLP 和 PPO clipped update 思想：候选编码 32→16，保持/动作分数，池化状态 critic；本轮新建输入特征，不直接加载旧 100 维模型，不能称为冻结旧模型的单因素对照。终局奖励=-全窗口平均响应/100，前面各步奖励为0，gamma=1，GAE lambda=.95。已有成本进入响应，不二次惩罚。

预设规模：12 个训练配置、6 个检查配置，每配置4个可行初始布局；种子17/29；每组每种子最多512次决策交互；2条独立检查流。检查集只在训练结束使用，不调参挑检查点。其结果仅判断代码闭环及初步行为，不能作为正式优越性证据。

必要审计：保持及一次 t=0 调整与共享执行原语一致；正成本动作不重置队列；到达恰好落在切换边界的处理确定；两次调整成本累计；全部请求完成；峰值布局内存不超限；输出种子级平均/P95、调整次数、提前停止、第二步收益及完整原始日志与模型。

发布说明：R116 相似度/阈值探测及敏感性网格不在本仓库。通用四函数工作流与布局运算已移至同目录的 `workflow_core.py`；此协议仅记录本实验所需的执行语义。
