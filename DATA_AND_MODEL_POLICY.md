# Data and model release policy

This repository is intended to publish the method and experiment code without requiring the authors to publish trained model weights or redistribute upstream datasets.

## Model weights

Trained PPO/RF checkpoints are research artifacts produced by the authors and are not included in this repository. The public code may document the method and an author-approved training protocol so that readers can train their own models. Sensitive hyperparameters can remain private as well. A reader-trained checkpoint is a new run and is not guaranteed to reproduce the exact decisions or numbers obtained with the authors' frozen checkpoints.

Results that depend on a frozen checkpoint must be described as evaluations of the authors' private checkpoint. The source can retain the expected checkpoint hash as an identity/provenance check, but a hash does not provide the weights. Do not describe the source-only release as an exact, turnkey reproduction of those frozen-checkpoint results.

## Input data

- For synthetic workflows, capacities, and request streams, publish the generator code, seed values, schema, and generation parameters. The package includes deterministic R187 profile generation, R366's synthetic eight-function profile generator, and Azure minute-window preprocessing; generated copies do not need to be committed.
- Exact historical R218/R366 manifests and frozen target layouts are separate experiment artifacts and are not regenerated by those generic generators. Identify this boundary clearly; do not present a fresh generated run as the same frozen evaluation.
- For Azure-derived real request traces, cite the upstream dataset and describe the exact extraction, window-selection, and preprocessing steps. Prefer a small downloader/transformer and checksums over committing a duplicate of the full upstream dataset. Check the upstream terms before redistributing any extracted trace.
- Platform-specific workflow fixtures can be described by their DAG, function count, resource assumptions, and profile identifier. The repository need not bundle a separately downloadable full dataset if those workflow inputs can be generated from included code; otherwise include a compact, licensed fixture or a reproducible recipe.

## What readers can reproduce

The current staging area contains source and protocol snapshots only. R187 can generate a fresh deterministic synthetic profile manifest and train from scratch. R218 evaluates historical profile sets and author-trained model artifacts that are not staged. R366 can regenerate the synthetic eight-function profile and Azure-derived request windows, but the live replay also requires a compatible external companion tree and the private R361/R363 source, target manifests, and checkpoints; its controller does not train those models. These paths are not turnkey reproductions of the authors' frozen results.

The public release should state this boundary plainly. It is reasonable to publish source, generators, and protocols while keeping the trained weights and private experiment artifacts with the authors. The OpenFaaS controller accepts `R366_PRIVATE_ARTIFACT_ROOT` for the separately supplied frozen model and audit artifacts; it refuses to silently substitute a different frozen controller.

## Azure trace used by the OpenFaaS replay

The R366 stream is derived from the public Azure Functions 2019 trace distributed by the [Azure Public Dataset project](https://github.com/Azure/AzurePublicDataset), specifically `invocations_per_function_md.anon.d01.csv`. The [official dataset archive](https://github.com/Azure/AzurePublicDataset/releases/download/dataset-functions-2019/azurefunctions_dataset2019_azurefunctions-dataset2019.tar.xz) is the source for the released trace. Retain the dataset's CC BY attribution and cite Shahrad et al., “Serverless in the Wild: Characterizing and Optimizing the Serverless Workload at a Large Cloud Provider,” USENIX ATC 2020.

The CSV contains per-function minute counts, not per-request timestamps or workflow DAGs. In our replay, the selected function sequence is only an ingress-rate proxy for a separate synthetic eight-function diamond. The release includes the sequence-preparation script, not the downloaded CSV or generated stream JSON. Its use and interpretation are documented in `openfaas-replay/PROTOCOL.md`.
