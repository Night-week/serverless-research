# R361：8 函数真机回放策略训练

## 目标

为 8 函数菱形工作流的真机回放准备同条件模型：EASR 完整系统、GRL 原目标适配器、GRL 响应目标适配器。EASR 的压力门控消融复用同一 PPO+RF 检查点，回放时关闭压力规则，不单独训练。Whole32、Greedy Fusion、Critical-path Fusion 是非学习基线，不需要模型。

## 训练环境隔离

- 训练计算在与 OpenFaaS/Kubernetes 隔离的计算环境中运行；主机标识和私有目录已从发布副本中删除。
- 脚本只调用本地仿真器；不访问 OpenFaaS Gateway，不创建、删除、扩缩或重启 Kubernetes/OpenFaaS 服务，不发送回放请求。
- 训练进程以低优先级运行，绑定 CPU 28–31，Python 数值库单线程。训练输出只写入本实验 `outputs/`。
- 主机现有服务和 R352 目录保持不动。R361 使用独立代码目录、状态文件和日志。

## 工作流和数据

- 工作流：R328/R352 profile `326001`，8 函数 diamond。
- 请求流：R332 冻结的 Azure Functions 分钟调用序列；训练 28 个窗口，验证 4 个 `mid_cv_p10` 窗口，留出测试 4 个 `mid_cv_p50` 窗口。
- 决策时刻：请求流开始 15 秒后，使用截至该时刻观测到的信息。
- 切换代价：目标布局改变且新增融合服务时计一次并行 Ready 代理 4.02 秒；排空与排队由事件仿真计算；旧服务 teardown 和目标预热为零。
- 测试窗口不参与训练、RF 拟合、Whole32 选择、checkpoint 选择或阈值选择。

## 训练模型

- EASR：每个种子训练 32,768 次 PPO 动作调用，再用相同 Azure 训练集拟合 RF。压力门阈值固定为 1.0；RF 标签阈值固定为 Whole32 平均响应至少改善 3%。
- GRL 原目标：保留 GRL-Orch 原生复合目标配置，从头训练并按验证集选择 checkpoint 和融合阈值。
- GRL 响应目标：沿用相同 GRL 架构、动作和训练流程，响应权重为 1、成本权重为 0，保留 OOM 项；按同一验证集选 checkpoint 和阈值。
- 种子：601、631、659。各模型顺序训练，每次只运行一个策略种子。
- EASR 关闭压力门控：复用上述 EASR PPO+RF 权重，在推理时只关闭压力覆盖规则。

## 输出和完成标准

每个种子的检查点、RF、训练摘要与留出布局写入 `outputs/`。总状态写入 `outputs/status.json`；最终汇总为 `outputs/summary.json`，真机回放目标为 `outputs/live_targets.json`。三个学习策略全部完成 3 个种子且逐项产物存在后，才记录 `R361_ALL_FINISHED`。

本任务只训练仿真模型并冻结真机回放目标，不在训练阶段评价或声称真机收益。
